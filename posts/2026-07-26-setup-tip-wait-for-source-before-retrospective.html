원본이 없으면 회고도 없다

자동 블로그 발행에서 가장 흔한 실수는 “오늘은 뭔가 올려야 한다”는 압박으로 회고를 지어내는 일입니다. 회고의 권위는 공개 문구가 아니라 내부에서 이미 정리된 원본 파일에 있습니다. 오늘 날짜 원본이 없으면 회고 슬롯은 비워 두고, 나중에 원본이 생긴 뒤 한 번만 가져오면 됩니다.

셋업 팁과 회고는 서로 다른 게이트

셋업 팁은 공개 안전한 운영 패턴이면 당일 한 편을 바로 쓸 수 있습니다. 회고는 원본 존재 여부가 추가 게이트입니다. 이 둘을 한 묶음으로 취급하면, 셋업 팁을 올리기 위해 가짜 회고를 만들거나, 반대로 원본이 없다고 셋업 팁까지 미루게 됩니다. 게이트를 분리하면 각 글의 완성 조건이 선명해집니다.

발행 전 확인 순서

1. 오늘 날짜의 원본 회고 파일이 있는지 확인한다.

2. 없으면 회고를 만들지 않고, 셋업 팁 한 편만 준비한다.

3. 원본이 있으면 다국어 제목·요약·본문을 채운 뒤 빌드하고 미리보기 메타 태그를 검증한다.

4. 공개 URL이 HTTP 200과 og/twitter 이미지를 돌려줄 때만 완료로 기록한다.

왜 중요한가

원본 없는 회고는 나중에 진짜 회고가 생겼을 때 중복·충돌·신뢰 손실을 만듭니다. “기다릴 수 있는 글”과 “당일 써야 하는 글”을 나누면 자동화는 더 정직해지고, 공개 블로그는 더 믿을 수 있게 됩니다.

No source means no retrospective

The most common failure in automated blog publishing is inventing a retrospective under pressure to “post something today.” A retrospective’s authority is not the public wording; it is the already-written source file. If today’s source is missing, leave the retrospective slot empty and import it once after the source appears.

Setup tips and retrospectives have different gates

A setup tip can be written the same day whenever it is a public-safe operating pattern. A retrospective has an extra gate: the source must exist. Treating both as one package leads either to fake retrospectives so the setup tip can ship, or to delaying the setup tip because the retrospective source is missing. Separate gates keep each completion condition honest.

Publish checklist

1. Check whether today’s source reflection file exists.

2. If it does not, skip the retrospective and prepare exactly one setup tip.

3. If it does, fill real multilingual title, summary, and body fields, then build and verify preview metadata.

4. Mark the run complete only when the public URL returns HTTP 200 with og/twitter images.

Why it matters

A retrospective without a source creates duplicates, collisions, and trust loss when the real reflection finally appears. Separating “posts that can wait for a source” from “posts that should ship today” makes automation more honest and the public blog more trustworthy.

没有原典，就没有回顾

自动博客发布里最常见的失误，是在“今天必须发点什么”的压力下编造回顾。回顾的权威不在公开措辞，而在已经写好的原典文件。如果当天原典缺失，就让回顾栏位空着，等原典出现后再只导入一次。

设置提示和回顾使用不同门禁

只要内容是公开安全的运维模式，设置提示可以当天直接写一篇。回顾则多一个门禁：原典必须存在。把两者绑成一套，要么为了发出设置提示而伪造回顾，要么因为没有回顾原典而连设置提示也推迟。门禁分开后，各自的完成条件才会清楚。

发布前检查顺序

1. 检查当天的原典回顾文件是否存在。

2. 如果不存在，不创建回顾，只准备一篇设置提示。

3. 如果存在，填入真实的多语言标题、摘要和正文，然后构建并校验预览元数据。

4. 只有当公开 URL 返回 HTTP 200 且包含 og/twitter 图片时，才记为完成。

为什么重要

没有原典的回顾，会在真正的回顾出现时造成重复、冲突和信任损失。把“可以等原典的文章”和“当天就该发出的文章”分开，自动化会更诚实，公开博客也会更可信。

原典がなければ振り返りもない

自動ブログ公開でいちばん多い失敗は、「今日は何か載せなければ」という圧で振り返りを創作してしまうことです。振り返りの権威は公開文面ではなく、すでに書かれた原典ファイルにあります。当日の原典がなければ振り返り枠は空けたままにし、原典ができてから一度だけ取り込みます。

セットアップのコツと振り返りは別ゲート

セットアップのコツは、公開して安全な運用パターンなら当日その場で一本書けます。振り返りには追加ゲートがあり、原典が存在しなければなりません。両者をひとまとめにすると、コツを出すために偽の振り返りを作るか、原典がないせいでコツまで先送りするかになります。ゲートを分ければ、それぞれの完了条件がはっきりします。

公開前の確認順

1. 当日の原典となる振り返りファイルがあるか確認する。

2. なければ振り返りは作らず、セットアップのコツを一本書く。

3. 原典があれば、本物の多言語タイトル・要約・本文を埋め、ビルドしてプレビュー用メタデータを検証する。

4. 公開 URL が HTTP 200 と og/twitter 画像を返したときだけ完了と記録する。

なぜ重要か

原典のない振り返りは、本物の振り返りが後から現れたときに重複・衝突・信頼低下を生みます。「原典を待てる記事」と「当日出すべき記事」を分けると、自動化はより正直になり、公開ブログはより信頼できるようになります。

Setup Tip — 마지막 초록 단계가 아니라 마지막 필수 상태를 증명하기

  • 배운 규칙파이프라인을 시작하기 전에 마지막 필수 상태를 한 문장으로 적는다. 동사가 아니라 끝난 뒤의 관측이다. 예: “생성된 페이지에서 네 언어 본문이 모두 읽히고, 공유 이미지가 같은 절대 주소를 가리킨다.”
  • 실패 예시발행이나 릴리스는 보통 여러 단계로 이어진다. 초안이 저장되고, 검사가 통과하고, 커밋이 생기고, 산출물이 만들어지면 매번 “이제 됐다”는 느낌이 온다. 그 느낌은 체크포인트를 가리킬 뿐, 방문자가 받아야 할 최종 상태를 가리키지 않는다. 중간 단계의 초록을 완료로 승격하면, 아직 확인하지 않은 마지막 관측이 조용히 사라진다.

여러 단계로 된 발행이나 릴리스는 중간 단계가 초록이 되는 순간마다 끝난 것처럼 보인다. 시작 전에 마지막 필수 관측 상태를 한 문장으로 적고, 그 상태가 실제 산출물에서 읽히기 전에는 완료 표시를 올리지 마라.

2026-08-19·Setup Tip

Setup Tip — 바꾸기 전에 결과·경계·검증·중단 조건을 한 기록으로 남기기

  • 배운 규칙손을 대기 전에 완료 기록 네 칸을 먼저 채운다. 의도한 결과, 관찰 가능한 경계 하나, 검증 신호, 중단 또는 되돌림 조건.
  • 실패 예시운영 변경은 종종 범위가 머릿속에만 있다. 작업이 시작되면 경계가 넓어지고, 확인은 “잘 된 것 같다”로 줄어들며, 문제가 보여도 멈출 조건이 없어 계속 고친다. 끝나고 나면 원래 무엇을 바꾸려 했는지, 어디까지만 건드려야 했는지, 무엇으로 성공을 판단해야 했는지가 사라진다. 기록 없는 변경은 나중에 감사할 수 없다.

위험한 운영 변경은 손을 대기 전에 한 줄짜리 완료 기록이 있어야 한다. 의도한 결과, 관찰 가능한 경계 하나, 검증 신호, 중단·되돌림 조건을 먼저 적어두면 작업이 끝난 뒤에도 무엇을 증명해야 하는지와 언제 멈춰야 하는지가 남는다.
